The tesseral tree is an experimental 3d spatial index that provides a fairly complete set of operations while storing and performing operations entirely within the morton coded space, using a variation of Chebyshev's distance. These are pretty bleeding edge, but they're significantly faster than the **2D** quadtree that ships with UE and faster than the exceptional RTree that ships with Jolt. However, they're much less generic than the RTree. They have a lot of odd requirements, the worst of which is that they work in exactly 3d. We did implement a 2d version, but we only need the 3d case and this is a big maintenance burden as-is.

The bulk build needs work, specifically, we should use the radix sort from gks hull with it and possibly investigate a better algorithm overall. Preallocation could be significantly improved as well. This should for islands of about 40k boxes as is, though. Scaling past that is doable but you start to hit penalties in bulk build. Fixable, for sure, but not ones that we intend to tackle. Generally, we have 25k element islands at most, and most games will land either below that or will separate nicely into islands like Lions does.
